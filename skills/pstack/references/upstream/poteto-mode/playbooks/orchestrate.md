### Orchestrate

Read the Pi execution contract before planning a standing multi-day program. This adaptation preserves one owner per artifact, observable verification, and independent acceptance. It does not provide Cursor cloud agents, a durable agent store, or automatic restart recovery.

1. Pin the program's goal, scope, repository, authority, stop conditions, and observable end predicate. Inventory the installed Agent and workflow capabilities before dispatch. A program needing unattended restart recovery or cloud execution has an explicit missing-capability gate.
2. Ground the affected systems and design the dependency graph. Assign one implementation owner per coherent unit. Keep shared writes serial or separate worktrees. The root owns synthesis, integration, and acceptance; leaf workers own bounded implementation.
3. Record standing orders and a decision trail in an authorized local artifact. Record task IDs, file scopes, branch/head evidence, verification receipts, unresolved findings, and write ownership. Do not invent an orchestration-store path or helper CLI.
4. Launch independent units through Agent, at most three active by default. Use SubagentWorkflow only with explicit orchestration authorization. Its pipeline stages perform bounded work; a barrier needs a real cross-item dependency. Preserve all required coverage and report missing results.
5. On native completion, collect the actual result and inspect the artifact. A code-ready unit gets an independent reviewer and real boundary verification. Bind acceptance to the verified head or artifact revision. A changed revision requires checking which receipts remain valid.
6. Correct confirmed findings through the implementation owner. Missing tools, failed launches, and uncertain verification remain blockers. A retry preserves the scope and reports the prior failure; it does not silently change engines or weaken gates.
7. Integrate and publish only within the operator's authority and repository rules. Report completed units, actual verification, open blockers, and the next frontier. Schedule audits only when the operator explicitly requests a cadence.
8. Before shutdown, stop or hand off owned work and record the resume capsule. Local child execution is not promised to survive Pi shutdown. Resume from current files and revision evidence, not stale agent IDs.

**Reply:** completed frontier, verification receipts, open gates, decision-trail path, and platform limits.
