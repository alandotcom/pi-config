### Autopilot-full

Read the Pi execution contract. This playbook needs an explicit grant to build and publish an independent queue. Full rigor alone does not grant PR creation, pushes, or merges. Pi's local agents are not durable cloud owners.

1. Pin the independent queue, dependency graph, allowed repositories and branches, publication authority, completion predicate, and stop conditions. Confirm the host supports the requested unattended lifetime; report missing durability before starting.
2. Ground and architect each unit. Assign one local general-purpose agent with the bundled worker brief per coherent implementation. Keep concurrent writers in disjoint scopes or worktrees. The parent retains PR operations and required reviews; leaf owners do not spawn children or claim merge authority.
3. Record an early decision trail and source/head evidence. Build and verify one reviewable unit at a time. Publish snapshots only when authorized, using repository checks and branch rules. Preserve existing changes.
4. Independently verify every code-ready head through general-purpose agent with the bundled reviewer brief and the real affected surface. Run the repository's mandatory review workflow. Compare the load-bearing behavior against the baseline where meaningful. A failed or unavailable lane is not a pass.
5. Send confirmed findings to the owner in one scoped correction. A changed head needs a fresh acceptance decision and renewed affected proof. Keep the root's verdict separate from the worker's self-report and CI status.
6. Merge only the verified authorized head through the forge's supported API and repository gates. Re-read merge state after the action. A green check list or bot approval alone does not authorize or prove a merge.
7. Audit on native completions. Schedule recurring audits only with an explicit operator cadence. After any shutdown, reconstruct from branch, PR, and verification artifacts; do not claim local owners survived.
8. Close only when the queue's end predicate holds, no delegated writes remain, and the post-merge checks required by the repository pass. Report omissions and remaining failures explicitly.

**Reply:** verified and merged units, head evidence, unresolved gates, decision-trail path, and any reduced runtime capability.
